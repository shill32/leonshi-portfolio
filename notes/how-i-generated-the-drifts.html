How I generated the drifts

One point field, one renderer, and a collection of drifts generated in the shader.

The animation began as a lab. I wanted motion that felt drawn: dark particles on paper, enough depth to suggest volume, and no color competing with the work.

The point field

Each frame draws 262,144 points. The browser uploads one index per point; the vertex shader turns that index into a position. There are no stored meshes. Each drift is an equation evaluated on the GPU.

That constraint shaped the look. The same field can resolve as a tesseract, folded membrane, manifold, molecular chain, or amorphous body. Depth changes point size, opacity, and tone. The fragment shader softens each point into a small grain of ink.

One renderer

The lab, the hyper review, this note, and the museum all call the same renderer. A drift selected in the lab is the exact drift that appears elsewhere. Keeping one implementation eliminated inconsistencies from approximate ports.

The museum changes only presentation: it increases scale and density, then reduces both for drifts that become too heavy at that setting.

Motion and input

Scroll selects a new drift. The shader blends the old and new positions with eased interpolation, so one geometry passes through another instead of cutting between scenes. Pointer movement adds a local tangential force measured inside the canvas bounds.

The renderer pauses when the page is hidden, limits pixel density, and respects reduced-motion preferences. On smaller screens, the same field remains interactive without changing the drift itself.

Curation

The broad archive was useful for finding families, but not every generated drift belonged in the museum. Inflating vesicles and dividing amoebas were cut. The retained collection favors structures with depth, asymmetry, and a clear silhouette.

The work is still procedural, but the selection is deliberate. The renderer supplies variation; the museum keeps only the drifts worth looking at again.
